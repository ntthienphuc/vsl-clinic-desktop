# VSL Clinic — UI/UX audit, 15 November 2026

## Product and observed flow

Windows desktop app for a doctor and a deaf patient, on one split screen or two monitors. Doctors start a conversation, speak/type or select a phrase, watch incoming patient words, then end the session. Patients watch an avatar and Vietnamese text and sign into the camera; their screen must remain passive. Vietnamese and English are interface languages only.

Baseline: Git `a1e3d97`, installed 0.6.4. Native observation at 754×779 content pixels: idle doctor screen and quick-phrase dialog. The native passive patient screen was also observed; runtime, keyboard and viewport evidence is recorded in the polish report. React 19.3.1, TypeScript 5.9.3, Vite 8.3.4, Electron 44.9.2, Three.js/VRM, local Python/FastAPI. `/doctor` and `/patient` routes, native HTML dialogs, Lucide icons, Nunito, existing teal/neutral styles in styles.css, workspace.css and clinic-ui.css. Existing `t()` translations and shared desktop language state must be retained.

## Findings before implementation

| Priority | Screen and evidence | User impact | Correction and verification |
| --- | --- | --- | --- |
| P1 | Doctor, actual split window: tall composer pushes patient response/history below fold; narrower CSS puts both aside cards in a row. | Doctor scrolls away from incoming words while speaking. | Fit simultaneous composition/response at supported split widths; readable stack at high zoom. Check 375, 570, 754/768 and 1440 widths. |
| P1 | Quick phrases, observed modal: 44 choices on open, six chips, overlapping “Hướng dẫn & hỗ trợ” and “Hỏi thêm & hướng dẫn”, repeated near-identical phrases. | Finding an appropriate question takes unnecessary scanning. | One library for phrases/words/practice, useful default selection and task-based categories, global accent-insensitive search, visible result count and clear filter recovery. |
| P1 | Patient “Bụng” / avatar voice reported by owner as “í bụng”; clips are generated by splitting a shared TTS batch. | Extraneous audio obscures the sign label. | Inspect exact clips/timings; replace faulty audio with a bounded first-word context clip and preserve original evidence. Verify waveform/ASR and actual playback; don't call an unmeasured cause proven. |
| P1 | Installer always copies GPU and CPU runtime, no user choice. | CPU-only machines consume unnecessary disk; installation cannot express the user's choice. | Clear CPU/GPU step, hardware-derived default, CPU fallback preserved for GPU selection; verify both installation manifests and startup preference. |
| P2 | Composer has two library entry points with separate dialogs; placeholder is the only visible field instruction; selected mode lacks aria-pressed. | Duplicated navigation and weaker keyboard/screen reader feedback. | Shared library, visible input label, named states, restore focus to composer after a selection. |
| P2 | Conversation status is hidden below 1100px; mute state copy conflates unavailable microphone with not-yet-started. | Doctor has less certainty about what is running or how to recover. | Keep concise state text visible, show actionable unavailable/muted feedback and pending actions. |
| P2 | Three layers of incremental CSS include unused patient feedback/uncertainty styles and conflicting sizing. | Maintenance risk and inconsistent behavior across widths. | Consolidate touched rules/tokens, remove proven obsolete blocks, don't rewrite the rendering architecture. |
| P2 | Source README contains 72-motion counts, language switch in either window and old installer paths. | Instructions contradict the installed app. | Replace current usage section with verified versioned instructions; retain old evidence as history. |

No P0 established in the observed idle/selection flows. Final verification must include camera unavailable, loading/disconnected state, long text, no search results, English, keyboard modal behavior, rapid actions, pause/reset and both communication directions.

## Design direction

Calm clinical workspace: keep teal for actions, dark readable text, light neutral surfaces, green ranked patient words, amber only for doctor drafts requiring review. Semantic labels must accompany color. Retain Nunito and Lucide, use a compact 4/8/12/16/24 spacing rhythm, 14px secondary copy and 16px controls, larger conversation text. Prefer one clear start/end action and grouped secondary settings. No decorative gradients, new fonts, dependencies or onboarding tour. Motion is limited to useful feedback; reduced motion disables decorative transitions, never the essential sign animation.

Preserve passive patient display, Vietnamese signing/readout, word-by-word speech, no beeps/confirmation, top-3 physician result view, exact original messages, speech/sign timeline, session cleanup, settings persistence, local-only runtime and current recognition/model contracts. Added avatar vocabulary is a separate inventory from fixed 100/400 recognition labels.
